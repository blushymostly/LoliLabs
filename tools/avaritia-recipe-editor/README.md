# Avaritia Recipe Editor 1.0.0

Небольшой отдельный редактор рецептов Re-Avaritia для TMR-dev. Minecraft может
быть закрыт; редактор читает предметы, переводы, иконки и JSON-рецепты из сборки.
Внешний интернет и установка Java не нужны — используется Java из Prism.

## Запуск и работа

Дважды щёлкните `Start.cmd` в этой папке или `Avaritia Recipe Editor.cmd`
в корне TMR-dev.

1. Выберите уровень верстака: 1/2/3/4 — сетка 3×3/5×5/7×7/9×9.
2. Найдите предмет слева по названию или ID. Один клик выбирает кисть,
   двойной клик или Shift+клик задаёт результат. Можно перетаскивать предметы.
3. Рисуйте ингредиенты ЛКМ по сетке. ПКМ очищает клетку, Ctrl+клик берёт её
   ингредиент. Есть зеркало, поворот, отмена и повтор изменений сетки.
4. Для тега выберите «Теги» либо введите `#forge:ingots/iron` в поле кисти.
   Альтернативы можно задать JSON: `[{"item":"minecraft:iron_ingot"},{"item":"minecraft:gold_ingot"}]`.
5. Укажите ID рецепта, результат и его количество. При необходимости включите
   «Без формы» или задайте NBT результата в SNBT.
6. Нажмите «Сохранить» / Ctrl+S. Затем выполните `/reload` в игре.

Вкладка «Рецепты сборки» импортирует существующие рецепты Avaritia из JAR.
Сняв фильтр «Только Avaritia», можно преобразовать JSON-рецепт обычного верстака
в рецепт Avaritia. Его ID сохраняется: после сохранения это будет явная замена
исходного рецепта. Для нового рецепта задайте собственный ID, например
`loli_labs:crafting/my_panel`.

Вкладка «Мои рецепты» открывает сохранённые рецепты, делает копии и удаляет
переопределения. После удаления переопределения исходный рецепт из мода снова
появится при `/reload`. Импорт и экспорт отдельного JSON доступны вверху.

## Куда записываются изменения

Относительно папки TMR-dev:

- Проект: `minecraft/kubejs/avaritia-editor/recipes.json`.
- Генерируемый KubeJS: `minecraft/kubejs/server_scripts/avaritia_editor.js`.
- Резервные копии перед сохранением: `minecraft/kubejs/avaritia-editor/backups/`.

Скрипт удаляет только конкретные ID из проекта и добавляет их новые версии через
`event.custom(...).id(...)`. JAR модов и чужие KubeJS-файлы не меняются.
Не редактируйте avaritia_editor.js вручную: управляйте им через редактор.
Если проект изменился в другом окне, сохранение остановится вместо перезаписи.

Каталог строится по ресурсам установленных модов. Иконки сложных трёхмерных
предметов могут отображаться упрощённо; ID или тег всегда можно ввести вручную.
Динамические рецепты из произвольных JS-скриптов не импортируются; они не
исполняются редактором. Стандартные item/tag/альтернативы и NBT-ингредиенты
поддерживаются; специальные типы ингредиентов без item/tag не редактируются этой версией. Доступен только крафт Avaritia; компрессор и кузнечные рецепты
в этот редактор не входят.

## Проверки и исходники

Формат сверён с сериализаторами установленной Re-Avaritia 1.4.2.
Восемь экспортов (все уровни, shaped/shapeless) успешно прочитаны настоящими
сериализаторами Avaritia в изолированном Forge. Дополнительно прошли 37 проверок
редактора, импорт/обратный экспорт 94 рецептов Avaritia и проверка генерируемого JS.
Каталог TMR-dev: 7823 модели предметов и 843 тега на момент проверки.
Автоматический захват окна Windows не удался; интерактивную проверку мышью
не заявляем выполненной.

Сборка: `pwsh -File build.ps1`.
Самопроверки: `java -Djava.awt.headless=true -jar dist/avaritia-recipe-editor-1.0.0.jar --self-test <новая папка>`.
Каталог: `java -Djava.awt.headless=true -jar dist/avaritia-recipe-editor-1.0.0.jar --catalog-check <папка экземпляра>`.
Проверка игровыми сериализаторами: `pwsh -File check-native.ps1` после подготовки
изолированного окружения штатным `loli-labs/check-runtime.ps1`.

Программа написана на Java 17/Swing; Gson 2.10 из Prism поставляется в dist/lib.
